## 系统分层总览

所有密码项分四层，从外到内：

1. **代码托管层** —— 管"代码仓库"的门（GitHub / Gitee）
2. **服务器管理层** —— 管"云服务器"的门（SSH / 宝塔）
3. **应用运行层** —— 程序自己要用的钥匙（写在 .env 配置文件里）
4. **应用内用户层** —— 网站"里面"的账号

## 第一层：代码托管层

### SSH 密钥（当前唯一推送方式）
- **作用**：`git push` / `git pull` 时验证开发者身份，全程不传密码
- **位置**：Mac 的 `~/.ssh/` 目录下一对文件：`id_ed25519`（**私钥**，绝不复制、绝不给任何人）+ `id_ed25519.pub`（**公钥**，可公开），公钥已登记到 GitHub、Gitee、服务器
- **复制公钥的方法**：【Mac终端】`pbcopy < ~/.ssh/id_ed25519.pub`（内容直接进剪贴板不上屏，去目标网页粘贴即可）
- **私钥丢失不可怕**：网站运行完全不依赖这把钥匙。硬盘坏了/私钥丢了，只需在新电脑重新生成一对钥匙、把新公钥重新登记到三个平台，10 分钟搞定、数据零损失。要防的是"泄露"而不是"丢失"
- **SSH vs HTTPS+令牌**：令牌像"口令暗号"——一串可被偷走的字符，会过期、会在 Mac 钥匙串里缓存错乱（2026-07-29 的推送 403 就是这么来的）；SSH 像"指纹验证"——私钥不出电脑、不过期、更安全。**结论：用 SSH**。GitHub 旧的两个令牌已删除

## 第二层：服务器管理层

服务器：阿里云 47.100.106.213，两个项目共用。通向它的"三扇门"：

1. **阿里云网页控制台**（aliyun.com 登录）——"房东的合同管理处"：续费、重装系统、防火墙端口、AccessKey 管理，不进入服务器内部
2. **服务器 SSH 登录**——"进屋干活的门"：进入服务器的命令行
3. **宝塔面板**——"屋里权限最高的管家"：以 root 身份运行的可视化管理网页

> 阿里云控制台里的 Workbench"远程连接"不是第四扇门——它是第 2 扇门的**浏览器版**，登录后身份同样是 admin，权限完全一样。

### 服务器 SSH 登录（admin 账号）
- **作用**：登录服务器命令行做日常运维（看日志、重启 pm2 等）
- **方式**：【Mac终端】`ssh admin@47.100.106.213`，已配 SSH 密钥免密
- **权限**：普通权限，**无 sudo**。（sudo = "以最高管理员 root 的身份执行这一条命令"，像借老板的印章；admin 不在允许名单里，需要 root 权限的操作一律走宝塔）

### 宝塔面板登录密码 ⭐ 权限最大
- **作用**：服务器管理网页（端口 8888），面板以 root 身份运行，等同"服务器万能钥匙"
- **能干什么**：网页终端（root 权限）、文件管理器改配置、重启服务
- **实战记录**：2026-07-29 数据库密码失联时，靠宝塔网页终端强制重置解救；同日用它完成萌宠 MC_JWT_SECRET 配置

## 第三层：应用运行层（.env 配置文件中）

程序**启动时读取一次**，改完配置必须重启程序才生效。

### 萌宠 mc（Flask + SQLite + 阿里云 OSS）

配置文件位置：
- 服务器：`/www/wwwroot/aiflowin.top/.env`
- Mac 本地：`mc/.env`

密码项：
1. **OSS_ACCESS_KEY_ID / OSS_ACCESS_KEY_SECRET**（阿里云 AccessKey，ID 为 LTAI 开头 24 位，Secret 30 位）
   - 作用环节：上传/删除鸟类照片时，后端调用阿里云 OSS API
   - 换钥匙的地方：阿里云控制台 → AccessKey 管理
   - 验证方法：网站上传一张新照片成功即生效
2. **SMTP_PASS**（QQ 邮箱 184345297@qq.com 的 16 位授权码）
   - 作用环节：程序发通知邮件（非主流程）
   - 换钥匙的地方：QQ 邮箱网页版 → 设置 → 账号 → 生成授权码
3. **MC_JWT_SECRET**（64 位随机字符，`openssl rand -hex 32` 生成，2026-07-29 配置）
   - 作用环节：萌宠有完整的邮箱+密码登录体系，登录后发放 7 天有效的 JWT 通行证（Cookie 名 `mc-token`），此密钥就是"盖章印泥"，用途与心芽的 JWT_SECRET 完全等同
   - ⚠️ 教训：不配置此项时，程序会退回使用写死在公开代码里的默认值（启动日志出现"[安全警告]"），等于印章人人可见，必须配置；换印章后所有已登录用户需重新登录

萌宠**没有**的：数据库密码（SQLite 是本地文件，程序直接读写，无连接认证）。

服务器重启方式（宝塔 root 终端）：
```
pkill -f "python3.8 -m server.app"
cd /www/wwwroot/aiflowin.top
nohup python3.8 -m server.app > mc_server.log 2>&1 &
```

### 心芽 xinya（Next.js + PostgreSQL + Prisma）

配置文件位置：
- 服务器：`/www/wwwroot/xinya/.env.production`
- Mac 本地：`xinya/.env` 和 `xinya/.env.production`（三处需保持同步）

密码项：
1. **DATABASE_URL 中的数据库密码**（`postgresql://xinya:密码@localhost:5432/xinya_db`）
   - 作用环节：每一次数据读写，密码不对则整站瘫痪（报错 P1000）
   - 换钥匙的方法：宝塔 root 终端执行 `sudo -u postgres psql -c "ALTER USER xinya WITH PASSWORD '新密码';"`
   - ⚠️ 教训：密码只用**字母+数字**，特殊符号会被终端命令曲解导致密码"失联"
2. **JWT_SECRET**（64 位随机字符，`openssl rand -hex 32` 生成）
   - 作用环节：登录后每次请求的"通行证盖章"验证；一换所有人被登出（正常现象）
3. **SMTP_PASS**（QQ 邮箱 1243177461@qq.com 的 16 位授权码）
   - 作用环节：用户邮箱登录时发验证码邮件（主流程，失效则新用户无法登录）
4. **DEEPSEEK_API_KEY**（DeepSeek AI 服务钥匙）
   - 作用环节：写完心得后，AI 自动生成复习题目和要点总结（代码 `lib/deepseek.ts` 调用）
   - 换钥匙的地方：DeepSeek 开放平台（platform.deepseek.com）→ API Keys
   - 备注：曾有个空壳配置 SILICONFLOW_API_KEY，代码从未使用，已于 2026-07-29 删除；DeepSeek 钥匙同日从服务器同步到 Mac 本地

心芽**没有**的：OSS AccessKey（不使用对象存储）。

服务器重启方式（admin SSH 终端）：
```
pm2 restart xinya
```

## 日常安全守则

1. 真实密钥只存在于：服务器/本地的 .env 文件 + 密码管理工具，**绝不写进任何 .md 文档、代码或 Git 提交**
2. .env 类文件必须在 `.gitignore` 中（两个项目均已配置）
3. 改完任何 .env 后必须重启对应程序才生效
4. 一旦怀疑泄露：立即轮换（换钥匙），比重写 Git 历史更重要——旧钥匙作废后，历史泄露即失去危害
5. 修改 .env 时警惕隐形回车符（\r），可用 `grep -q $'\r' 文件名` 检查
