## 1. 功能概述

在心芽中新增一个独立的「学习助手数字人」模块，名为**豆苗**。

豆苗以**当前注册用户的所有已发布心得（不含草稿）**为知识来源，与用户进行文字对话：
- 解答用户关于自己心得的问题（回顾、总结、关联、延伸提问）
- 分析用户的知识喜好与薄弱环节（结合答题记录）
- 对话全程仅限心得知识范围，超出范围的提问按兜底话术拒绝

用户可自定义豆苗的性格与回答方式（3 维预设 + 自由描述润色）。

本功能为**独立模块，可整体启用/删除**，删除后不残留任何代码与数据，保持心芽源码干净。

## 2. 用户诉求与决策记录

### 2.1 需求来源（用户原话要点）

1. 心得数量超过 50 条时启动学习助手角色——**后改为：手动开启，与条数无关**

3. 用户可设置数字人性格与回答方式（女生、娃娃音、苏格拉底式提问等）
4. 讨论内容仅限用户的心得范围，超出范围的兜底话术拒绝回答

## 3. 角色与知识边界

### 3.1 角色定义

- 名称：豆苗
- 定位：心芽的学习心得小助手，像朋友一样陪用户回顾、梳理、深化自己的心得知识
- 身份透明：不假装真人、不编造生活经历
- 知识来源唯一：**当前用户所有 isDraft=false 的心得**（标题、内容、标签、mood、keyPoints、关联 EntryLink）
- 回答原则：基于心得内容回答；检索不到就如实说明，**不编造**；超出心得范围拒绝

### 3.2 允许回答的范围

| 类别 | 是否允许 | 说明 |
|------|---------|------|
| 心得内容回顾/总结 | ✅ | 如「我写过哪些关于 React 的心得」 |
| 心得间关联提问 | ✅ | 如「我这两篇心得有什么联系」 |
| 薄弱环节分析 | ✅ | 结合对话推断 + QuizRecord 答题记录 |
| 知识喜好总结 | ✅ | 用户问「我对什么感兴趣」时回答 |
| 出题考问（基于心得） | ✅ | 基于检索到的心得出复习题 |
| 基本寒暄 | ✅ | 你好/谢谢/辛苦了 等可正常回应 |
| 无关但无害话题 | ❌ | 天气/电影/笑话/新闻/游戏 等 → 兜底话术 |
| 敏感/危险内容 | ❌ | 一律拒绝（走系统安全边界） |
| 已被删除心得的内容 | ❌ | 检索无果 → 「没找到相关话题」兜底 |

### 3.3 兜底话术（两套）

**越界拒绝**（问题不在心得范围）：
> 这个话题我还不太了解，系统设置了我仅能聊聊心得方面的话题，我们聊聊心得吧～

**检索无果**（问题在范围内但没搜到相关内容，含已删除心得的内容）：
> 我在你的心得里没有找到相关的话题呢～要不要换个问题，或者先去写一篇相关的心得？

### 3.4 心得数量不足的降级提示（0 条 / 很少）

- 用户心得为 **0 条**：豆苗页面显示灰色头像 + 降级提示文字（文案待定稿，开发前经用户确认），**隐藏聊天输入框**，提供「去写心得」入口
- 心得很少（>0 但数量不足以支撑可靠回答，阈值待定）：可正常对话，但豆苗在开场/回答中提示「知识库还比较小，回答范围有限」（具体触发与文案开发前与用户确认）

## 4. 性格与回答方式设置

### 4.1 三个预设维度（骨架，最高约束）

**维度一：语气风格**（默认：温暖鼓励）

| 选项 | 说明 |
|------|------|
| ⚡ 简洁直接 | 干脆利落，不废话 |
| 🌸 温暖鼓励 | 温和友善，多说肯定 |
| 🎈 活泼俏皮 | 轻松有趣，偶尔调侃 |
| 📚 沉稳知性 | 稳重理性，有书卷气 |
| 💮 娃娃音 | 可爱俏皮，语气词多（呀～嘛～啦） |

**维度二：指导方式**（默认：启发引导）

| 选项 | 说明 |
|------|------|
| 🧠 苏格拉底式提问 | 以问代答，引导用户自己思考 |
| 📖 直接解答 | 清晰直接给出答案和解释 |
| 🔍 启发引导 | 先给提示等用户思考，不会再说答案 |
| 🤗 鼓励陪伴 | 重在共情和肯定，压力小 |

**维度三：角色称呼**（默认：我 / 你）

| 选项 | 说明 |
|------|------|
| 👋 我 / 你 | 最自然中性，像朋友聊天 |
| 👩‍🏫 老师感 | 自称老师，说话带指导感 |
| 🤝 咱们 / 伙伴 | 像一起学习的伙伴 |

### 4.2 自由描述（局部润色）

- 文本框，可选填；示例提示：「你是一个温柔的女老师，喜欢用提问引导我思考，偶尔会活泼地开个玩笑」
- **作用**：仅在预设骨架上做局部润色（语气词、表情符号、用语习惯等细节），**不覆盖、不推翻预设选项**
- 为空时：仅按预设执行

### 4.3 规则

1. 预设 = 骨架 = 最高约束；自由描述只做加法润色 → 不存在互相矛盾的情况
2. **对话中不能修改人设**；只能在「豆苗设置」中修改
3. 修改设置后对**后续新对话**生效，历史对话不变
4. 首次使用：进入豆苗页面时展示 3 步设置向导（每步一个维度、一行选项单选 + 最后一步可选自由描述）
5. 向导可跳过 → 全部使用默认值（语气：温暖鼓励 / 指导：启发引导 / 称呼：我·你）
6. 设置完成后进入聊天界面

## 5. 知识检索机制与 Prompt 约束

### 5.1 三级检索渠道（独立并行，各自返回结果）

用户提问时，在用户自己的心得中从三个渠道**独立并行**检索：

| 渠道 | 优先级 | 匹配规则 | 上限 |
|------|--------|---------|------|
| **标签匹配** | 高 | 问题关键词与心得所属标签名称（Tag.name）匹配，含父子标签 | 最多 5 条 |
| **标题匹配** | 中 | 问题关键词与心得标题（Entry.title）模糊匹配 | 最多 3 条 |
| **内容匹配** | 低 | 问题关键词在心得正文（Entry.content）、keyPoints、mood 中出现 | 最多 5 条 |

**三条渠道不要求全部命中**。各渠道独立检索，各自返回命中的心得条目。最终注入 LLM 的上下文为所有渠道结果的**合并列表**，但**每条都带有优先级标记**。

**优先级补位规则**：若高优先级渠道检索结果不足上限，空缺不补（标签未命中就是未命中，不拿标题匹配结果充高优先级）；低优先级渠道如标题匹配不足上限，内容匹配可按需增至最多 8 条，但**中/低优先级结果在回答中仅做补充，不可作主要论据**。

### 5.2 命中过多时的截断策略

如果检索结果总计超过 13 条，按以下规则截断和精炼：

1. **标签匹配 ≥ 3 条**时：按更新时间倒序取最近的 3 条作为「高优先级」输入；其余 1-2 条在末尾以「另外还有 N 篇相关心得（标签匹配）」简述
2. **内容匹配 ≥ 6 条**时：按问题关键词在正文中出现**频率降序**排列，取前 5 条；其余丢弃
3. 三条渠道总计超过 13 条时：丢弃全部「内容匹配」结果中相关性最低的部分，优先保标签匹配的完整性

### 5.3 未命中处理

三级检索均未命中 → 不注入心得内容，直接走「检索无果」兜底话术。

### 5.4 检索结果注入格式

检索结果格式化后注入 LLM 上下文，格式如下：

```
【心得检索结果·给豆苗的知识源】

检索时间：{当前时间}
命中总计：{N} 篇
以下是按优先级排序的检索结果：

---
优先级：高 | 匹配方式：标签匹配 | 《心得标题》
标签：#标签1 #标签2
更新时间：2026-08-20
摘要：{keyPoints 或正文前 150 字摘要}
---
优先级：中 | 匹配方式：标题匹配 | 《心得标题》
标签：#标签1
更新时间：2026-08-15
摘要：{keyPoints 或正文前 150 字摘要}
---
优先级：低 | 匹配方式：内容命中 | 《心得标题》
标签：#标签2
更新时间：2026-08-10
摘要：{关键片段…}
```

摘要字段优先使用 Entry.keyPoints（用户已写的要点），无 keyPoints 时取正文开头 150 字。

### 5.5 大模型输出指令（Prompt 约束）

#### 5.5.1 基本回应规则

在 System Prompt 中固定写入以下指令（`{}`内为运行时填入的变量）：

```
## 关于心得检索结果的使用规则

你的记忆库中有上述检索到的心得内容。请完全基于这些内容回答用户的问题，
并严格遵守以下规则：

1.【优先级原则】回答时优先以「高优先级（标签匹配）」心得为第一依据，
「中优先级（标题匹配）」为辅助参考，「低优先级（内容命中）」仅做补充，
不得将低优先级内容作为主要论据。

2.【多结果提炼】当同一主题检索到多条心得时，回答的逻辑是：
   - 提取这 N 篇心得的共同观点
   - 指出它们之间的差异点（如有）
   - 用概括性语言回答，不必逐条罗列每篇的每个细节
   - 回答开头可告知用户「从 N 篇心得中找到了相关内容」

3.【矛盾处理】如果不同心得之间观点矛盾（如一篇说 flex 好用、另一篇说 flex 不好用），
必须如实指出这种矛盾，不得强行统一或忽略任一方。
   - 正确示范：「我看到你对这个话题的两种看法：在 X 篇里你觉得好用，
     在 Y 篇里你又遇到了问题。要不要我帮你梳理一下差异？」
   - 错误示范（禁止）：「你对这个话题的看法是一贯正面的」

4.【检索不到】如果在心得范围内但检索结果完全为空，
直接回复：「我在你的心得里没有找到相关的话题呢～要不要换个问题，或者先去写一篇相关的心得？」

5.【禁止编造】任何时候不得编造心得中不存在的内容。如果对某些细节不确定，
如实说「你的心得里没有提到这个细节」。

6.【回答风格】按用户设置的性格选项组织语言（目前设置如下）：
   语气风格：{tone_selection}
   指导方式：{teach_selection}
   角色称呼：{call_selection}
   自由润色：{free_description}

7.【检索标签展示】回答前在气泡上方生成一行检索来源标记，格式为：
   - 如果来自标签匹配：「🥷 从 N 篇心得中找到（标签匹配）]
   - 如果来自标题匹配：「📖 从 N 篇心得中找到（标题匹配）」
   - 如果混合命中：「从 N 篇心得中找到相关内容」
   仅当用户问的是与具体心得内容相关的问题时才展示；基本寒暄不给标签。
```

#### 5.5.2 宽泛提问的特殊处理

当用户提问命中 10 条以上心得时，属于「宽泛提问」，按以下规则处理：

```
【宽泛提问处理规则】

如果定位到用户提问命中心得数量超过 10 条，说明问题过于宽泛，
你应按以下方式回答：

1.【按标签分组】先按标签对命中心得分类，告诉用户：
   「涉及的内容比较多，我帮你按标签理一下：
    #React（3 篇）、#CSS（2 篇）、#工具（1 篇）……先从哪个开始聊？」

2.【按时间总结】如果用户明确要求回顾/总结（如「我最近怎么样」「最近写了什么」）：
   取最近 5 篇心得做简要总结，然后说「以上是你最近几篇心得的要点，想深入聊哪篇？」

3.【引导缩小范围】回答末尾加一句引导语，帮助用户聚焦：
   「涉及的内容比较多，你可以再具体一点（比如加上标签或时间范围），
   我帮你找得更准～」

4.【例外】如果用户问的是「我写过哪些关于 Xxx 的心得」——这是合理列举问题，
   直接列出命中的心得标题 + 一句话摘要即可，每条一行。
```

#### 5.5.3 三级匹配与检索范围的关系示意图

```
用户提问
  │
  ├─ 越界判定（问题是否在心得范围）
  │    ├─ 否 → 兜底话术①（越界拒绝）
  │    └─ 是 → 执行三级检索
  │
  ▼
三条渠道并行检索
  │
  ├─ 标签匹配（最多5条）→ 标记【高优先级】
  ├─ 标题匹配（最多3条）→ 标记【中优先级】
  └─ 内容匹配（最多5条）→ 标记【低优先级】
  │
  ▼
合并结果，格式化为检索上下文
  │
  ├─ 总计 > 13 条 → 按截断策略（§5.2）精炼
  ├─ 总计 > 10 条 → 另触发宽泛提问处理（§5.5.2）
  └─ 总计 = 0 条  → 兜底话术②（检索无果）
  │
  ▼
注入 Prompt + 本次提问 → DeepSeek 生成回答
  │
  ▼
在 UI 展示检索标签 + 回答气泡
```

### 5.6 实现约束

- 检索范围：`Entry WHERE userId = 当前用户 AND isDraft = false`（排除草稿；已删除心得天然不在范围内）
- 检索实时进行：用户编辑/删除心得后，下次对话读到的是最新数据，无需额外同步机制
- 内容匹配的正文抽取上限：每篇心得最多截取正文前 500 字进行关键词匹配（更长的正文仅匹配开头部分，全文匹配消耗过大且首页权重最高）
- 注入 LLM 的摘要长度上限：每篇心得摘要 ≤ 150 字（可复用现有关键点叫 `keyPoints` 的蒸馏模式）

## 6. 对话与历史

### 6.1 会话形态

- **单一持续会话**：用户只有一条与豆苗的对话流（豆包式），无会话列表、无多会话管理
- 关闭页面再进入：接着上次的对话继续（历史消息可向上滚动翻看）
- 手机与桌面同一界面，仅宽度自适应（见界面自适应规范 §9）

### 6.2 历史保留

- 会话消息存入数据库，多设备同步
- 上下文窗口：注入 LLM 的历史为**最近 30 轮**（超出部分截断，仅存数据库可翻看不参与生成）
- 用户可在界面清空对话历史（清空后豆苗重新打招呼，记忆清单不受影响）——清空入口与交互细节开发前确认

### 6.3 回答要求

- 回答长度随问题复杂度自然变化（原型演示：简洁问题短答、分析问题可展开）
- 回答前在 UI 展示「检索标签」（如「从 23 篇心得中找到 3 篇 · 标签匹配：React」），提示用户回答依据来源
- 生成的回答**不可编造**心得中不存在的内容

## 7. 记忆系统（喜好与薄弱环节）

### 7.1 记录内容与来源

| 类型 | 内容 | 来源 |
|------|------|------|
| 知识喜好 | 用户反复记录/追问的主题领域 | 对话推断 + 心得标签/内容统计 |
| 薄弱环节 | 理解困难、易错的知识点 | 对话推断 + QuizRecord 答题记录（正确率/连错），双来源 |

### 7.2 写入规则（参考球球人格宪法「选择性记忆」）

只有满足以下条件之一才写入记忆，**不把每句话都变成记忆**：
1. 用户在对话中明确表达稳定偏好/困难（如「我觉得 CSS 布局好难」）
2. 同一主题在对话中重复出现（≥2 次）
3. 答题记录显示该主题正确率持续偏低（阈值开发前确认）
4. 用户明确要求豆苗记住（「记住我喜欢 xxx」「这个我老是错」）

### 7.3 范围限制

- **仅限心得知识方面**的喜好与薄弱点
- 敏感内容（健康、家庭、财务、身份等）即使出现也不记录
- 记录的是「主题 + 一句话描述 + 来源 + 时间」，不记录对话原文

### 7.4 可见性与删除

- 界面提供「🧠 豆苗了解的我」清单：逐条展示记忆（标签：兴趣/薄弱 + 内容 + 来源）
- 每条记忆可单独删除；删除后豆苗不再使用该记忆
- 记忆用于回答（如「我哪里薄弱」）时的上下文注入

### 7.5 主动提醒

- **本期不主动提起**薄弱环节（仅用户问到时回答）；主动提醒机制列入 P2

## 11. LLM 调用设计（概念层）

### 11.1 Prompt 分层结构（参考球球 08-人设与Prompt系统）

```
Layer 1: 豆苗身份（固定）        — 你是豆苗，心芽的学习心得小助手…
Layer 2: 人设骨架（按设置生成）   — 语气风格 + 指导方式 + 角色称呼（三维预设）
Layer 3: 自由描述润色（可选）     — 局部细节
Layer 4: 边界与安全规则（固定）   — 仅限心得范围；不编造；越界拒绝规则 + 兜底话术
Layer 5: 检索到的心得上下文（动态）— 三级匹配结果（标题/标签/要点/正文片段）
Layer 6: 薄弱/喜好摘要（动态）    — 命中相关记忆时注入
Layer 7: 对话历史（动态）        — 最近 30 轮
Layer 8: 本次用户问题（动态）
```

### 11.2 意图判定（双重边界，参考球球 companion-agent-boundaries）

生成回答前先做一次**意图判定**（可用 LLM 结构化输出或规则，开发时定）：
1. 问题是否属基本寒暄 → 正常回应
2. 问题是否在心得知识范围内 → 否：直接返回越界兜底话术，**不调用生成接口**（或调用但 Prompt 强制拒绝——开发时确定，倾向先判定后生成，省成本）
3. 范围内：执行三级检索 → 命中：注入上下文生成回答；未命中：返回检索无果兜底

### 11.3 成本记录

每次调用记录到消耗表：userId、调用时间、预估输入/输出 token、估算费用、问题摘要（脱敏），用于后台追溯分析（管理端展示界面列入 P2，先落数据）。

### 11.4 模型与降级

- 沿用现有 DeepSeek 接入（`lib/deepseek.ts` 模式，OpenAI 兼容）
- API 失败：返回友好错误提示，不阻塞页面

## 14. 验收要点（需求级）

- [ ] 豆苗以当前用户非草稿心得为知识源，能回答心得回顾/总结/关联类问题
